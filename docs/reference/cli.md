# Command line

Every tool of the workflow, with all its options. Run the commands from the repository
root; relative paths in the options of `export.py`, the converters and `rollout.py` are
resolved against it. `--help` prints the same list for every tool. How the tools work
together: [how CrashDefNet works](../concepts/overview.md).

| Tool | Stage |
|---|---|
| [export](#export) | raw data → dataset folder |
| [tfrecord_to_d3plot](#tfrecord_to_d3plot), [tfrecord_to_vtk](#tfrecord_to_vtk) | benchmark → LS-DYNA runs or VTK time series |
| [remesh_pole](#remesh_pole) | OpenRadioss runs → raw data with a meshed pole |
| [train](#train) | dataset → trained model |
| [rollout](#rollout) | model → rollout of a split |
| [plot_losses](#plot_losses), [evaluate_run](#evaluate_run) | one run on its own |
| [compare_paper](#compare_paper), [check_protocol](#check_protocol) | runs against the papers and against each other |

| [animate_rollout](#animate_rollout) | GIF of a rollout |
| [app](#app) | the whole workflow in the browser ([the app](../guides/app.md)) |

## export

Export simulation runs (DeepMind TFRecord, LS-DYNA d3plot, VTK time series) into a dataset folder: dataset.db, metadata.json, normalizer.json. Without arguments the small test set of deforming_plate is written.

```bash
python -m dataset_preprocessor.export [options]
```

| Option | Default | Description |
|---|---|---|
| `--config CONFIG` | – | TOML file that defines the dataset: raw data, components with their roles, features (docs/guides/export.md); options given here override it |
| `--list-parts` | `False` | List the parts of the first run with nodes, elements, node type and thickness, and their roles with --components, then stop |
| `--raw-format {tfrecord,d3plot,vtk}` | `tfrecord` | Raw data: DeepMind TFRecord (standard), d3plot of OpenRadioss or LS-DYNA runs (docs/guides/openradioss.md, docs/guides/ls-dyna.md) or VTK time series |
| `--raw-dir RAW_DIR` | – | Directory with meta.json and the .tfrecord or the run folders (default: datasets/deforming_plate/raw_dataset; d3plot: datasets/deforming_plate/raw_d3plot; vtk: datasets/deforming_plate/raw_vtk) |
| `--sources NAME [NAME ...], --source-tfrecord NAME [NAME ...]` | `test.tfrecord` | Where the runs come from, one name, or three, one per split: train val test. TFRecord: the file inside --raw-dir (test.tfrecord: 100 trajectories); d3plot / vtk: the folder below --raw-dir (&lt;name without .tfrecord&gt; for converted runs), else all runs below --raw-dir |
| `--contact-radius CONTACT_RADIUS` | – | World edge radius, in the length unit of the raw data; default: collision_radius of meta.json (required for d3plot / vtk raw data without meta.json) |
| `--contact-pairs [A:B ...]` | – | Contact rules of raw data with components (LS-DYNA and VTK parts): world edges only between these pairs, e.g. plate:impactor plate:plate (self-contact), also with patterns (box_\*:beam_\*); none given: every pair |
| `--deck-walls, --no-deck-walls` | `--deck-walls` | D3plot: use the rigid walls of the decks (\*RIGIDWALL_PLANAR, /RWALL/CYL) as node features |
| `--length-unit {m,cm,mm}` | `m` | Unit of the lengths in the raw data (positions, contact radius, e.g. mm for LS-DYNA models); the values are kept, the reports convert to SI |
| `--stress-unit {Pa,kPa,MPa,GPa}` | `Pa` | Unit of the stress in the raw data (e.g. MPa for LS-DYNA models in mm, t, s); the values are kept, the reports convert to SI |
| `--out-dir OUT_DIR` | `data/deforming_plate_s10_small` | Output directory (== [data].data_dir in the config) |
| `--n-train N_TRAIN` | `8` | Train trajectories |
| `--n-val N_VAL` | `2` | Validation trajectories |
| `--n-test N_TEST` | `2` | Test trajectories |
| `--select-seed SELECT_SEED` | – | Draw the trajectories of each split at random with this seed (stored in metadata.json); default: the first ones |
| `--num-steps NUM_STEPS` | `40` | Frames per trajectory (samples per trajectory = num_steps - 1) |
| `--time-stride TIME_STRIDE` | `10` | Raw frames between two selected frames |
| `--history {0,1}` | `0` | 1: append velocity_prev (+ stress_prev) to the node features (enables residual_target / scheduled sampling); 0 = paper |
| `--prev-stress, --no-prev-stress` | `--prev-stress` | With --history 1: include stress_prev |
| `--overwrite, --no-overwrite` | `--overwrite` | Replace an existing dataset.db |

**LS-DYNA and VTK raw data: components, result fields, static node features, run parameters and free rigid parts**

| Option | Default | Description |
|---|---|---|
| `--components [PATTERN=ROLE ...]` | – | What goes into the dataset: name patterns of the parts with their role (deformable, actuator, fixed, free_rigid); every other part is left out; instead of --free-rigid-parts, --exclude-parts, --actuator-parts and --clamped-parts; default: every part, roles from the raw data |
| `--global-features [NAME ...]` | – | Run parameters in the dataset, one input per graph; default: all that the runs have |
| `--globals-file GLOBALS_FILE` | – | JSON file with the run parameters of all runs, by the name of the run folder; default: a globals.json in every run folder |
| `--fields [FIELDS ...]` | – | Further result fields per state as targets, each under its own name; vtk: point or cell fields, e.g. plastic_strain (vectors: one per component); d3plot: plastic_strain, thickness (shells) |
| `--static-fields [STATIC_FIELDS ...]` | – | Static node features; vtk: point or cell fields of the first state (vectors: one per component); d3plot: thickness, initial_velocity and the material properties of the deck density, youngs_modulus, poisson_ratio, yield_stress (default: thickness and initial_velocity where the runs have them) |
| `--free-rigid-parts [PART ...]` | – | Rigid parts whose motion results from the crash (e.g. a barrier with mass): the model predicts it and the rollout moves each as a rigid body; default: rigid parts are actuators, their motion given. d3plot: \*MAT_RIGID and /RBODY parts without prescribed motion, by title; vtk: any parts |
| `--exclude-parts [PART ...]` | – | D3plot only: parts left out of the export, named as the components, e.g. display models written as shells: their elements and the nodes only they hold; nodal fields are averaged without them; default: every part stays |

**VTK raw data (--raw-format vtk): field names and parts**

| Option | Default | Description |
|---|---|---|
| `--stress-field STRESS_FIELD` | `stress` | Point or cell field of the target stress: scalar, or stress tensor (6 / 9 components, gives the von Mises stress); '': no stress |
| `--node-type-field NODE_TYPE_FIELD` | `node_type` | Point field with the node types 0 / 1 / 3; absent: all normal |
| `--displacement-field DISPLACEMENT_FIELD` | – | Positions = points + this field (exports with reference geometry) |
| `--node-id-field NODE_ID_FIELD` | – | Point field with node IDs: copies of a node in several parts become one node; None: the field marked as global IDs (e.g. UserID of ParaView's LS-DYNA reader), '': ignore IDs |
| `--part-field PART_FIELD` | – | Cell field with part IDs for --actuator-parts / --clamped-parts; None: parts named by their block or file |
| `--actuator-parts [ACTUATOR_PARTS ...]` | – | Parts whose nodes are actuators (motion given, e.g. rigid impactor) |
| `--clamped-parts [CLAMPED_PARTS ...]` | – | Parts whose nodes are clamped |

**large data**

| Option | Default | Description |
|---|---|---|
| `--resume, --no-resume` | `--no-resume` | Continue an interrupted export in --out-dir (same options) after its last complete trajectory |
| `--edge-stats-stride EDGE_STATS_STRIDE` | `1` | Fit the edge statistics (a contact search per frame) on every k-th sample of a trajectory only; 1 = all |
| `--block-mb BLOCK_MB` | `1024` | LS-DYNA / VTK: read the frames of a run in blocks of about this size (MB), so a run need not fit into memory |

## rollout

Autoregressive rollout of a trained model over every trajectory of a split.

```bash
python predict/rollout.py [options]
```

| Option | Default | Description |
|---|---|---|
| `--config CONFIG` | – | TOML file with the settings of the rollout and of the evaluation after it (docs/guides/rollout.md); options given here override it |
| `--checkpoint CHECKPOINT` | `checkpoints/example_run/best_model.pt` | Trainer checkpoint (.pt) |
| `--data-dir DATA_DIR` | `data/deforming_plate_s10_small` | Dataset.db + normalizer.json — the dataset the checkpoint was trained on |
| `--output-dir OUTPUT_DIR` | – | New or empty folder (default: rollouts/&lt;time&gt;_&lt;training run&gt;_&lt;checkpoint&gt;_&lt;split&gt;) |
| `--split {train,val,test}` | `test` | Split of the dataset to roll out |
| `--max-sequences MAX_SEQUENCES` | – | Roll out only the first N trajectories (default: all) |
| `--start-frame START_FRAME` | – | Raw frame of the run the rollout starts from, its ground truth (default: that of the training, else the first frame of the dataset) |
| `--end-frame END_FRAME` | – | Raw frame of the run the rollout ends with (default: that of the training, else the last frame of the dataset) |
| `--max-steps MAX_STEPS` | – | Steps per trajectory (default: all) |
| `--device {auto,cpu,cuda}` | `auto` | Auto: the GPU if available |
| `--export-vtu, --no-export-vtu` | `--export-vtu` | Write one .vtu per step (prediction / ground truth / error); needs pyvista |
| `--one-step, --no-one-step` | `--one-step` | Also compute the one-step rollout metrics RMSE-1 (a second model call per step) |
| `--lazy, --no-lazy` | – | Read the frames from dataset.db on access instead of loading the split (default: as in the training) |
| `--evaluate, --no-evaluate` | `--no-evaluate` | Evaluate the run on this rollout right after it (utils/evaluate_run.py) |
| `--evaluation-output-dir EVALUATION_OUTPUT_DIR` | – | With --evaluate: new or empty folder for the evaluation (default: evaluations/&lt;time&gt;_&lt;run&gt;_evaluation) |
| `--animate, --no-animate` | `--no-animate` | Render one trajectory of this rollout as an animated GIF right after it (utils/animate_rollout.py); needs the .vtu export |
| `--animation-trajectory ANIMATION_TRAJECTORY` | – | With --animate: e.g. test_traj0136 (default: the trajectory at the median of the position error) |
| `--animation-output-dir ANIMATION_OUTPUT_DIR` | – | With --animate: new or empty folder for the GIF (default: evaluations/&lt;time&gt;_animation) |
